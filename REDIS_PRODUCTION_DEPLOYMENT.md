# Redis Production Deployment Guide

**Purpose**: Deploy production-ready Redis for Beakon microservices
**Time**: 15-30 minutes
**Audience**: DevOps, System Administrators

## Option 1: Managed Redis (EASIEST)

### AWS ElastiCache for Redis

**Setup Time**: 10 minutes

1. **Create ElastiCache Cluster**
   ```bash
   # Via AWS Console:
   # 1. Go to ElastiCache → Redis → Create
   # 2. Choose:
   #    - Engine: Redis 7.x
   #    - Node type: cache.t3.micro (dev) or cache.t3.small (prod)
   #    - Multi-AZ: Yes (for production)
   #    - Replicas: 1-2
   # 3. Security Group: Allow port 6379 from your services
   # 4. Parameter Group: default
   ```

2. **Get Connection Details**
   ```bash
   # After creation, note:
   # Primary Endpoint: your-cluster.abc123.cache.amazonaws.com:6379
   ```

3. **Configure Your Services**
   ```bash
   export REDIS_ENABLED=true
   export REDIS_HOST=your-cluster.abc123.cache.amazonaws.com
   export REDIS_PORT=6379
   export REDIS_PASSWORD=  # If auth enabled
   export REDIS_DB=0
   ```

**Done!** That's it. No maintenance required.

### DigitalOcean Managed Redis

**Setup Time**: 5 minutes

1. **Create Database Cluster**
   ```bash
   # Via DigitalOcean Console:
   # 1. Databases → Create → Redis
   # 2. Choose datacenter region
   # 3. Select plan (Basic starts at $15/month)
   # 4. Click Create
   ```

2. **Get Connection Details**
   ```bash
   # From Connection Details tab:
   # Host: your-redis-cluster-do-user-123456-0.b.db.ondigitalocean.com
   # Port: 25061
   # Password: <auto-generated>
   ```

3. **Configure Your Services**
   ```bash
   export REDIS_ENABLED=true
   export REDIS_HOST=your-redis-cluster-do-user-123456-0.b.db.ondigitalocean.com
   export REDIS_PORT=25061
   export REDIS_PASSWORD=<your-password>
   export REDIS_DB=0
   ```

**Done!** Automatic backups, monitoring included.

### Redis Cloud (Official)

**Setup Time**: 5 minutes
**Free Tier**: 30MB, perfect for testing

1. **Sign Up**: https://redis.com/try-free/
2. **Create Database**:
   - Select cloud provider (AWS/GCP/Azure)
   - Choose region
   - Free tier or paid plan
3. **Get Endpoint**:
   ```
   redis-12345.c123.us-east-1-2.ec2.cloud.redislabs.com:12345
   ```

**Done!** Managed by Redis creators, best support.

## Option 2: Self-Hosted Docker (THIS GUIDE)

### Prerequisites

- **Server**: AWS EC2, DigitalOcean Droplet, or any VPS
- **OS**: Ubuntu 20.04+ or Debian 11+
- **RAM**: Minimum 2GB (4GB recommended)
- **CPU**: 2+ cores
- **Disk**: 20GB+ SSD
- **Docker**: Installed

### Architecture

```
┌──────────────────────────────────────────────┐
│          Production Server (VPS/EC2)         │
│                                              │
│  ┌────────────┐  ┌──────────────────────┐   │
│  │   Redis    │  │  Redis Sentinel x3   │   │
│  │   Master   │◄─┤  (HA Monitoring)     │   │
│  │ Port 6379  │  │  Ports 26379-26381   │   │
│  └────────────┘  └──────────────────────┘   │
│        │                                     │
│        └─► Persistent Storage (SSD)         │
│                                              │
└──────────────────────────────────────────────┘
                     ▲
                     │
          ┌──────────┴──────────┐
          │                     │
    ┌─────┴──────┐      ┌──────┴──────┐
    │  Service 1 │      │  Service 2  │
    │ (SaaS Adm) │      │ (Tenant Adm)│
    └────────────┘      └─────────────┘
```

### Step-by-Step Deployment

#### 1. Server Setup

```bash
# SSH into your server
ssh root@your-server-ip

# Update system
apt-get update && apt-get upgrade -y

# Install Docker
curl -fsSL https://get.docker.com -o get-docker.sh
sh get-docker.sh

# Install Docker Compose
apt-get install docker-compose -y

# Verify installation
docker --version
docker-compose --version
```

#### 2. Upload Configuration Files

```bash
# On your local machine, copy files to server:
scp docker-compose.production.yml root@your-server:/opt/redis/
scp redis-production.conf root@your-server:/opt/redis/
scp sentinel.conf root@your-server:/opt/redis/
```

#### 3. Generate Strong Password

```bash
# SSH into server
ssh root@your-server-ip

cd /opt/redis

# Generate secure password
REDIS_PASSWORD=$(openssl rand -base64 32)
echo "Redis Password: $REDIS_PASSWORD"  # SAVE THIS!

# Update config files with password
sed -i "s/CHANGE_THIS_TO_STRONG_PASSWORD_MIN_32_CHARS/$REDIS_PASSWORD/g" redis-production.conf
sed -i "s/CHANGE_THIS_TO_STRONG_PASSWORD_MIN_32_CHARS/$REDIS_PASSWORD/g" sentinel.conf
```

#### 4. Start Redis

```bash
cd /opt/redis

# Start all services
docker-compose -f docker-compose.production.yml up -d

# Verify all containers are running
docker ps

# Expected output:
# beakon-redis-master       (port 6379)
# beakon-redis-sentinel-1   (port 26379)
# beakon-redis-sentinel-2   (port 26380)
# beakon-redis-sentinel-3   (port 26381)
# beakon-redis-exporter     (port 9121)
```

#### 5. Test Connection

```bash
# Test Redis master
docker exec -it beakon-redis-master redis-cli -a $REDIS_PASSWORD ping
# Expected: PONG

# Test sentinel
docker exec -it beakon-redis-sentinel-1 redis-cli -p 26379 sentinel master beakon-master

# Set test key
docker exec -it beakon-redis-master redis-cli -a $REDIS_PASSWORD SET test "Hello Beakon"

# Get test key
docker exec -it beakon-redis-master redis-cli -a $REDIS_PASSWORD GET test
# Expected: "Hello Beakon"
```

#### 6. Configure Firewall

```bash
# UFW (Ubuntu Firewall)
ufw allow 6379/tcp   # Redis
ufw allow 26379/tcp  # Sentinel
ufw allow 9121/tcp   # Metrics (optional)
ufw enable

# Or AWS Security Group:
# - Inbound: Port 6379, Source: Your microservices' security group
# - Inbound: Port 26379, Source: Monitoring tools (optional)
```

#### 7. Connect Your Services

```bash
# On your microservices servers, set environment variables:
export REDIS_ENABLED=true
export REDIS_HOST=<your-server-ip>  # Or domain name
export REDIS_PORT=6379
export REDIS_PASSWORD=<password-from-step-3>
export REDIS_DB=0

# Test from microservice server
redis-cli -h <your-server-ip> -p 6379 -a <password> ping
# Expected: PONG
```

### Monitoring & Maintenance

#### View Logs

```bash
# Redis master logs
docker logs beakon-redis-master -f

# Sentinel logs
docker logs beakon-redis-sentinel-1 -f
```

#### Check Redis Info

```bash
# Memory usage
docker exec -it beakon-redis-master redis-cli -a $REDIS_PASSWORD INFO memory

# Replication status
docker exec -it beakon-redis-master redis-cli -a $REDIS_PASSWORD INFO replication

# Statistics
docker exec -it beakon-redis-master redis-cli -a $REDIS_PASSWORD INFO stats
```

#### Prometheus Metrics

```bash
# Redis Exporter exposes metrics on port 9121
curl http://localhost:9121/metrics

# Integrate with Prometheus:
# Add to prometheus.yml:
scrape_configs:
  - job_name: 'redis'
    static_configs:
      - targets: ['<your-server-ip>:9121']
```

#### Backup & Restore

**Automatic Backups** (via config):
- RDB snapshots every 15 minutes
- AOF append-only file updated every second

**Manual Backup**:
```bash
# Trigger manual snapshot
docker exec -it beakon-redis-master redis-cli -a $REDIS_PASSWORD BGSAVE

# Copy backup files
docker cp beakon-redis-master:/data/dump.rdb ./backup-$(date +%Y%m%d).rdb
docker cp beakon-redis-master:/data/appendonly.aof ./backup-$(date +%Y%m%d).aof
```

**Restore**:
```bash
# Stop Redis
docker-compose -f docker-compose.production.yml down

# Copy backup files
docker cp ./backup-20250101.rdb beakon-redis-master:/data/dump.rdb
docker cp ./backup-20250101.aof beakon-redis-master:/data/appendonly.aof

# Start Redis
docker-compose -f docker-compose.production.yml up -d
```

## High Availability Testing

### Simulate Master Failure

```bash
# Stop master
docker stop beakon-redis-master

# Watch sentinel logs (failover should happen within 5-10 seconds)
docker logs beakon-redis-sentinel-1 -f

# Sentinel will automatically promote a replica to master

# Restart old master (becomes replica)
docker start beakon-redis-master
```

### Verify Failover

```bash
# Check current master
docker exec -it beakon-redis-sentinel-1 redis-cli -p 26379 sentinel get-master-addr-by-name beakon-master

# Your services should automatically reconnect to new master
```

## Performance Tuning

### Memory Optimization

```bash
# Check current memory usage
docker exec -it beakon-redis-master redis-cli -a $REDIS_PASSWORD INFO memory

# If using too much memory:
# 1. Increase maxmemory in redis-production.conf
# 2. Or enable key eviction (already set to allkeys-lru)
# 3. Restart Redis
docker-compose -f docker-compose.production.yml restart redis-master
```

### Connection Pooling

**In your Go services** (`internal/cache/redis.go`):
```go
client := redis.NewClient(&redis.Options{
    PoolSize:     50,  // Increase for high traffic
    MinIdleConns: 10,  // Keep connections ready
})
```

### Persistence Performance

**If high write load**:
- Change `appendfsync` from `everysec` to `no` (faster, less durable)
- Or disable AOF (RDB only): Set `appendonly no`

## Security Hardening

### 1. Enable TLS/SSL

```bash
# Generate certificates
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /opt/redis/certs/redis.key \
  -out /opt/redis/certs/redis.crt

# Update redis-production.conf:
port 0
tls-port 6380
tls-cert-file /tls/redis.crt
tls-key-file /tls/redis.key

# Update docker-compose.production.yml to mount certs
# Update REDIS_PORT=6380 in services
```

### 2. Rename Dangerous Commands

**In `redis-production.conf`**:
```conf
rename-command FLUSHDB ""
rename-command FLUSHALL ""
rename-command CONFIG "CONFIG_abc123"
```

### 3. Network Isolation

```bash
# Use Docker network instead of exposing ports
# Update docker-compose.production.yml:
networks:
  beakon-internal:
    internal: true  # No external access
```

## Troubleshooting

### Redis Won't Start

**Check logs**:
```bash
docker logs beakon-redis-master
```

**Common issues**:
- Permission denied → Check volume permissions
- Config syntax error → Validate redis-production.conf
- Port already in use → Change port or kill existing Redis

### Services Can't Connect

**Test connectivity**:
```bash
# From microservice server
telnet <redis-server-ip> 6379

# Or using redis-cli
redis-cli -h <redis-server-ip> -p 6379 -a <password> ping
```

**Check**:
- Firewall rules
- Redis bind address (should be 0.0.0.0, not 127.0.0.1)
- Password correct
- Network connectivity

### Out of Memory

**Check memory usage**:
```bash
docker exec -it beakon-redis-master redis-cli -a $REDIS_PASSWORD INFO memory
```

**Solutions**:
- Increase `maxmemory` in config
- Enable key eviction (already configured)
- Add more RAM to server
- Use multiple Redis instances

## Questions?

Common questions answered:

**Q: Do I need Redis for production?**
A: No, but it's recommended. System works fine with PostgreSQL-only.

**Q: What if Redis goes down?**
A: Services automatically fall back to PostgreSQL. Zero downtime.

**Q: How much faster is Redis?**
A: 10-30x faster than PostgreSQL for token operations.

**Q: Can I use Redis for other things?**
A: Yes! Use it for caching, rate limiting, pub/sub, leaderboards, etc.

**Q: What about Redis Cluster?**
A: For horizontal scaling beyond 1 server. Sentinel is enough for most cases.
